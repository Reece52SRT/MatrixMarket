# AI Usage Write-Up — Part 2

**Word count: ~420**

Generative AI (Claude, Anthropic) was used as a development accelerator for this phase,
under our direction and review. Below is a transparent account of what it was used for.

**Code architecture & scaffolding.** We used AI to generate the initial project scaffold for
both the Kotlin/Jetpack Compose Android app and the ASP.NET Core backend, based directly on
the architecture we specified in our own Part 1 Planning & Design document (MVVM pattern,
Retrofit + Repository layers, JWT authentication, the specific REST endpoints and data schemas
we had already designed). This included the DTOs, `ApiService` interface, repository classes,
`ViewModel`s, and Compose screens for each required and custom feature.

**Debugging & syntax correction.** During generation, the AI introduced a few Kotlin syntax
errors (e.g. malformed `sp()` calls, mismatched braces in one screen file) which were caught
and corrected in the same session before being committed.

**Boilerplate reduction.** Repetitive, well-understood code — DTO classes mirroring backend
models, GitHub Actions YAML for CI, `.gitignore`, EF Core entity configuration — was generated
by AI to save time, since this code follows well-documented conventions (ASP.NET Core docs,
Android developer docs) rather than requiring novel problem-solving.

**What we reviewed and adjusted ourselves:**
- All business logic for our three custom features (ISBN scanning flow, trade meeting
  confirmation flow, Student Score/badge thresholds) was checked against our own design intent
  from Part 1 and adjusted where the AI's first pass didn't match our vision.
- We will replace the placeholder `google-services.json` and Firebase Web Client ID with our
  own real Firebase project credentials before recording the demonstration video, since these
  cannot be generated by AI and must come from an account we control.
- We are responsible for testing the app end-to-end on a physical device, verifying the demo
  video shows genuine, unscripted app behaviour, and for all further feature work in Part 2
  submissions and the Final POE.

**Citation approach.** Where the AI referenced external documentation while writing code
comments (e.g. Android's `WorkManager`, ML Kit barcode scanning, JWT patterns in ASP.NET
Core), it followed the same official developer documentation we had already cited in our Part 1
Reference List, rather than introducing new unverified sources.

We have used AI as a coding assistant in the same spirit as a pair-programmer or code
generator (e.g. GitHub Copilot) — producing a first draft against our own specification, which
we then read, tested, corrected, and take full ownership of. No part of our written research or
design reasoning (Part 1) was AI-generated; this write-up concerns implementation of the Part 2
prototype only.
